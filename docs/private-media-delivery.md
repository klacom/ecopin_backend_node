# Authenticated private image delivery

Task-photo uploads persist `storage://<encoded bucket>/<object path>` references rather than signed URLs. The strict resolver also accepts existing public/authenticated/signed Supabase URLs from the configured project, discarding their query credentials. It rejects foreign hosts, unexpected buckets, malformed paths and traversal.

`GET /api/media/storage?bucket=...&path=...` authenticates the caller, checks suspension, and downloads through Supabase using that caller's JWT plus the anon/publishable key. It never uses the service key for delivery or falls back to a public/signed URL. Bytes use private/no-store caching, Authorization variance and sandbox/nosniff headers. The older task-photo endpoint delegates to the same delivery path.

Web galleries now resolve private references to authenticated byte requests and render temporary object URLs. Expired access tokens get one retry through the existing refresh API. Abandoned responses cannot replace the current image, and object URLs are revoked. Existing external/public images keep their existing behavior. Mobile photo widgets download private bytes with the native session, refresh once after 401, cancel abandoned requests, clear bytes on auth/source changes and preserve existing public-image caching/placeholders.

Verified locally: backend 32 suites / 224 tests; actual Storage/Auth/media router 166 checks including stable reference persistence, role mutations and current-readiness revocation; web resolver 4 tests plus 7 public-map tests, a successful 38-route production build and scoped lint with no errors; mobile full regression suite 111 tests and scoped widget/resolver/test analysis passed. Native widget tests render a valid PNG over localhost and verify source cancellation, logout clearance and one refresh after 401. Isolated Chromium renders the actual web component and verifies PNG/blob delivery, source changes, refresh once and same-tab logout clearance. That test reproduced a same-tab logout leak; the repair centralizes observable token changes across existing app auth writers. Client tests use synthetic localhost sessions; native Storage/Auth/router tests separately prove real local RLS. Browser harness/evidence are in the root optimization workspace.

The expanded native Storage matrix exercises all three buckets with anonymous, owner, unrelated owner, assigned crew, unrelated crew, officer and admin clients. It checks exact read bytes, uploads, deletion, denied direct update/upsert and preservation of existing bytes. Current policies deliberately have no UPDATE permission: replacement uses a new object path and reference switch plus durable old-object cleanup. Report Evidence currently permits owner-folder and staff access; assigned crew cannot read that bucket. This matrix proves current policy behavior, not report-to-evidence assignment support. Every disposable object and account is removed at the end of the run.

Cloudinary URLs used by existing report/evidence pipelines are preserved; this change does not make those external assets private.
